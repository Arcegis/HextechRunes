# 战斗中的即时金币

献祭、收集者、炽燃利息、小猪存钱罐、夺金和升级：王国资产在各自的模型 Hook 中等待原版 `PlayerCmd.GainGold`。金币归属于符文持有者；不以 `LocalContext` 筛选执行端，不追加金币同步消息。0.107.1、0.110.0、0.111.0 的原版命令均修改金币及历史记录、分发金币 Hook，仅音效按本地玩家判断。确定性来自各端执行同一触发链，不能从 UI 或本地回调补发。

- 献祭按自己回合开始时存活的敌人数发放；治疗与格挡加成不变。
- 收集者沿用真死亡判定及目标去重，击杀、处决和飞踢共享入口；飞踢必须等待异步发钱完成。
- 炽燃利息沿用灼烧伤害统计及演出怪排除；夺金沿用伤害来源判断。
- 小猪存钱罐的拾取 200 金币和受伤 20 金币都覆盖递归保护，默认禁用状态不变。
- 王国资产每个自己的回合额外获得当前层数的一半，整数向下取整，不增加 Power 层数，不改变原版战后收益。

鲜血神像的获得金币 Hook 仍然触发。小猪存钱罐、夺金和炽燃利息在自身发钱期间禁止自身重入，防止获得金币→鲜血神像伤害→受击/反击→再次发钱的循环；保护在 `finally` 中解除，后续独立伤害正常触发。收益时机改变后，获得金币的治疗/扣血也会逐次结算；复视的战后金币奖励加倍不再作用于这些战斗内收益。

`SavedCountThisCombat` / `SavedCounter` 保留原序列化身份，但新触发不再增加计数。旧存档已有未领取计数仍按原战后奖励路径发放一次后清零；只有这类遗留计数显示计数器。新产生的即时收益不会再次计入战后奖励。
