# 欧洛巴斯二次强化

五个原版角色的初始遗物已经升级后，再次获得欧洛巴斯之触会替换为对应的「先古遗物+」。原版只映射五件初始遗物，第一次升级后的遗物仍是 Starter 稀有度，因此会再次被选中，却因为没有升级映射而得到头环。

## 效果与展示

| 二次升级 | 效果 |
| --- | --- |
| 黑暗之血+ | 战斗胜利后回复 18 点生命；沿用原版死亡检查。 |
| 长蛇戒指+ | 自己的前 5 个回合额外抽 2 张牌。 |
| 天命所归+ | 战斗开始时获得 11 颗辉星；0.107.1 为 9 颗。 |
| 无界命匣+ | 战斗开始时召唤 10；自己的每个回合开始时召唤 3，包括首回合。 |
| 注能核心+ | 首回合开始时生成 5 个闪电；自己的闪电被动及激发数值额外增加 2。 |

天命所归+在原版先古版本基础上再增加一次原版升级增量：`先古值 × 2 − 初始值`。0.107.1 为 `6 × 2 − 3 = 9`，0.110.0/0.111.0 为 `7 × 2 − 3 = 11`。

图标、轮廓及大图通过 `IconBaseName` 复用对应原版遗物，不复制贴图。九语言标题在原名后加 `+`，描述及风味文本沿用原版语言模板，以各自 DynamicVars 显示新数值；原版缺少的语言字段使用原版英文回退。

## 获取与兼容边界

- `OrobasPlusUpgrades` 仅在本局启用海克斯时补充五个已升级遗物的映射。原版初始遗物的第一次升级保持不变。
- 启用判定复用 `HextechMayhemModifier.IsEnabledForRun`：优先读取本局冻结配置；单机旧局或控制台测试缺少 Mayhem modifier 时使用菜单开关，联机缺少快照时不使用各端本地配置。不能把缺少 modifier 直接等同于禁用，否则单机仍会回退为头环。
- 在 `TouchOfOrobas.GetUpgradedStarterRelic` 使用 postfix；只有原结果为头环才补映射，不覆盖其他模组已有的非头环升级结果。其他模组在其后改写返回值仍可能影响最终结果。
- `SetupForPlayer` 与 `AfterObtained` 继续由原版负责，因此事件获得和「欧洛巴斯的祝福」组合奖励共用同一条替换路径。沿用原版保存的 StarterRelic/UpgradedRelic ID，不额外存计数或使用随机数。
- 已持有「+」版时再获得欧洛巴斯之触，映射回同一种「+」版，原版仍执行移除和获得流程；不会继续叠加升级，也不会降成头环。此保护对已持有「+」版的存档一直生效。
- 模型继承 `RelicModel`，不继承 `HextechRelicBase`，因此不参加海克斯计数、重铸及候选生成。只注册到 EventRelicPool，排除商店和共享随机遗物注册。
- 保留 Starter 稀有度。原版图鉴只列角色 StartingRelics 和这些遗物的第一次升级结果，海克斯图鉴追加列表也不含这五件，因此默认隐藏；持有后的遗物栏及悬浮说明正常使用对应模型。

新增模型身份见 `src/Relics/Orobas` 与 `HextechCustomModelRegistry.EventRelicTypes`，后续不要改类名。联机各端需使用相同模型集合的构建。没有追溯恢复已经被头环替换掉的旧遗物。

## 验证范围

定向测试覆盖原版头环回退、五组二次升级、关闭时保持原行为、已有第三方映射、第三次升级、原版入口补丁、抽牌回合边界及闪电归属；另检查原版图标路径和三版本数值。遗物二次升级只需要一处映射 postfix。

单机缺少 modifier 的回归通过真实 `GetUpgradedStarterRelic` 补丁入口检查菜单开/关两种情况。旧实现会在启用用例返回头环；直接调用 `ResolveUpgrade(..., active: true)` 不能覆盖此故障。

0.107.1、0.110.0、0.111.0 均已编译通过，三个定向测试及补丁清单、补丁目标检查均通过；九语言与内容资源静态校验通过。完整多版本包已重新构建并按用户要求部署到本机游戏的 `Contents/MacOS/mods/HextechRunes`，部署内容与 `dist` 一致，部署包校验通过；尚未发布到工坊。

实机奖励动画、图鉴呈现、战斗效果、读档及多人联机留给用户验证；命令行测试不模拟这些 Godot 流程。

## 古老牙齿与永恒牌

特兹卡塔拉的余烬通过 `OnEnchant` 添加永恒。古老牙齿的原版选牌和新卡生成允许带附魔的初始牌，并复制升级与附魔，但随后的 `CardTransformation` 构造器及 `CardCmd.Transform` 都检查 `IsTransformable`。牌组里的永恒牌会在这里抛出异常；组合奖励顺序等待古老牙齿获得完成，因此欧洛巴斯之触也无法继续发放。

`ArchaicToothEternalHooks` 保留原版获取、选牌、生成及转换命令，仅补充三处挂钩：

| 目标 | 用途与边界 |
| --- | --- |
| `ArchaicTooth.AfterObtained` | 非跳过 prefix 建立本次转换的 AsyncLocal 作用域；原版返回 Task 后 finalizer 立即恢复调用者上下文，Task 完成或失败后停用作用域。 |
| `ArchaicTooth.GetTranscendenceTransformedCard` | postfix 记录原版实际选中的永恒牌，并确保转换结果保留永恒；附魔及升级仍由原版复制。预览调用只继承关键词，不授予转换权限。 |
| `CardModel.IsTransformable` | postfix 仅放行当前古老牙齿异步作用域中记录的那一张永恒牌；不修改 IsRemovable，也不影响同玩家的其他永恒牌。 |

三个版本缺少定向忽略永恒的转换 Hook/命令参数，因此使用上述局部作用域。不删除原牌关键词、不复制原版整段转换命令、不吞掉其他异常。作用域不保存、不依赖随机数和本地玩家身份，菜单及本局激活判断沿用统一入口。

定向回归从原版永恒牌转换异常开始，运行真实古老牙齿选牌、新卡生成和附魔复制；只替代转换命令的场景与动画部分，同时实际构造原版 CardTransformation。检查痛击+到破击+、余烬层数、0费、永恒、异步续体、调用者隔离及关闭开关后的原版拒绝。此检查不等同于完整奖励 UI 或联机实测。

永恒转换回归及补丁清单检查已在 0.107.1、0.110.0、0.111.0 通过，三个变体已打包部署到本机游戏目录，部署内容与 dist 一致。
