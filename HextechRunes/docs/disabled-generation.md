# 关闭模组时的原版生成隔离

菜单总开关按新一局配置生效，联机以房主同步的本局配置为准。已经冻结的本局状态不随菜单修改而改变。

## 遗物池与随机数

模型仍无条件注册，以保留存档、联机模型身份和百科内容。`SharedRelicPool.GetUnlockedRelics` 的窄范围后置补丁只排除 `HextechRelicBase`，保留原版和其他模组条目及顺序。符文和锻造器通过海克斯专用选择入口直接发放，不使用原版自然生成池。

原因是原版共享 `RelicGrabBag.Populate(IEnumerable<RelicModel>, Rng)` 会给 Starter 稀有度条目洗牌。即使它们最后不会掉落，也会消耗与遭遇/Boss 生成共用的 UpFront 随机数。生成完成后再移除条目无法恢复已经推进的随机数。过滤不依赖本地菜单值，避免联机房主配置尚未同步时产生不同候选池。

该池隔离同时适用于开启和关闭的新局，因此开启模组时的新局种子结果也可能与旧版本不同。旧存档已经生成的房间和遭遇不会被重置。

## 禁用分支

- 首次冻结前读取本局配置快照，禁用局不抽取符文稀有度和首个敌方海克斯。
- 保留联机 act-roll 配置同步；同步后立即冻结并检查总开关，在额外敌方海克斯抽取、地图修改和内容发放前返回。
- 卡牌奖励备选项在禁用局直接走原版 Generate；商店与奖励入口共用本局开关判定。
- 专用预设挑战仍沿用其独立配置规则；普通新局关闭开关时不进入海克斯玩法。

## 验证

维护目标为 0.107.1、0.110.0、0.111.0。自动化检查覆盖真实原版 RelicGrabBag 的随机数消耗及后续序列、冻结前后的开关状态、禁用检查与敌方内容生成的调用顺序，以及三个目标的补丁签名清单。原版 Starter 条目也保留，避免按稀有度误删第三方内容。

三个目标均构建成功（0 警告、0 错误），分别通过 266/266 项检查。

本地 dist 已生成稳定加载器和三个兼容 DLL，变体清单校验通过；PCK 挂载后逐项比对了 1412 个源文件的哈希，全部一致。沙箱内原版游戏打包进程退出异常，最终使用同版本 Godot 4.5.1 独立工具完成打包及验证，未部署或发布。

实机复测由用户完成：在 beta 0.111、相同角色/解锁/进阶/其他模组条件下，对比不加载海克斯与加载海克斯但菜单关闭的新局，使用种子 `QJ43VSY5UYFO` 检查一层 Boss、地图和奖励。这里的自动化随机数验证不等于已完成该种子的实机复现或联机测试。
